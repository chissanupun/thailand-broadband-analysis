# ข้อมูลและวิธีวิเคราะห์


---

## 3.1 ชุดข้อมูล

**Ookla Open Data** ให้ข้อมูลประสิทธิภาพอินเทอร์เน็ตรายไตรมาสในรูปแบบ tile แบ่งตามประเภทการเชื่อมต่อ (fixed, mobile) ที่ Quadkey zoom 16 (ขนาดราว 610×610 เมตร) แต่ละ tile มีค่าเฉลี่ย download, upload, latency พร้อมจำนวนครั้งที่ทดสอบ (Speedtest submission) กำกับมาด้วย เก็บเป็นไฟล์ Parquet บน Amazon S3 แบบ global ซึ่งงานนี้คัดกรองเหลือ 9 ประเทศเองภายหลัง รวม 12 ไตรมาส (Q1 2023–Q4 2025) ทั้งสองผลิตภัณฑ์ ได้ทั้งหมด 229,367,221 test อินโดนีเซียมากที่สุด 74.2 ล้าน ลาวน้อยที่สุด 875,799

**M-Lab NDT7** ให้ข้อมูลรายการทดสอบ (per-test) ในช่วงเวลาเดียวกันผ่าน BigQuery เก็บทั้ง timestamp และชื่อ ISP ดิบที่ tile ของ Ookla ไม่มี — ตรงนี้เองที่ทำให้ RQ3 กับ RQ4 เป็นไปได้ ปริมาณรวมทั้ง 9 ประเทศอยู่ที่ 760,607,387 test อินโดนีเซียมากที่สุด 367.2 ล้าน ลาวน้อยที่สุด 139,693 NDT7 ไม่ได้แยก fixed กับ mobile มาให้ในตัว ต้องจัดกลุ่ม IP ผู้ทดสอบเป็นบล็อก /24 (IPv4) หรือ /48 (IPv6) แล้วสุ่มตรวจ 5 IP ต่อบล็อกกับ flag `mobile` ของ ip-api ใช้เสียงข้างมากตัดสินทั้งบล็อก ถ้า 5 ตัวอย่างไม่ตรงกัน จะตรวจทุก IP ในบล็อกนั้นทีละตัว วิธีสุ่มแล้วค่อยยกระดับแบบนี้ลดเวลาการเรียก API จาก 27 วันเหลือไม่กี่ชั่วโมง ส่วนการจัดกลุ่มผู้ให้บริการใช้ **ASN** แทนชื่อ ISP ดิบจาก M-Lab ที่ไม่น่าเชื่อถือเมื่อข้อมูลมีขนาดใหญ่ เทียบกับ IP ที่มี label รายตัวอยู่แล้ว 5.24 ล้านตัวจากรอบ fetch ก่อนหน้า (84,137 บล็อก) วิธีนี้ให้ผลตรงกับคำตอบของ ip-api เองอย่างน้อย 99.15% ที่ระดับ IP เดี่ยว บล็อกที่ปนกันจริงมีเพียง 0.45% — แต่ผลเอกฉันท์ 5 ต่อ 5 เป็นแค่ขอบล่างของความเป็นเนื้อเดียวกัน ไม่ใช่หลักฐานยืนยัน เพราะไม่มี ground truth อิสระนอกเหนือจาก ip-api เอง

**ขอบเขตและข้อมูลอ้างอิง** bounding box ระดับประเทศมาจาก geoBoundaries ADM1 ส่วนการระบุจังหวัดใช้ point-in-polygon กับ GADM 4.1 ยกเว้นไทยที่ใช้ geojson 77 จังหวัดของโปรเจกต์เอง เพราะ GADM ไม่มีระดับการปกครองที่ละเอียดพอ และสิงคโปร์ที่ใช้ geojson 5 planning region ของโปรเจกต์เอง เพราะ GADM ไม่มีระดับ ADM1 เลยสำหรับนครรัฐ แต่ละแถวระดับ province-quarter ยังมีประชากร ความหนาแน่น GDP ต่อหัว และ internet-infrastructure tier แนบมาจากตารางอ้างอิงของโปรเจกต์ด้วย

## 3.2 การรวมข้อมูลและการกรอง

tile ของ Ookla ถูกจับคู่เข้ากับจังหวัดด้วย point-in-polygon กับ geojson ของแต่ละประเทศ แล้วรวมเป็นระดับ province-quarter แบบถ่วงน้ำหนักตามจำนวนครั้งที่ทดสอบของแต่ละ tile การถ่วงน้ำหนักไม่ใช่ทางเลือก เพราะจำนวนการทดสอบต่อ tile ต่างกันเป็นหลายเท่าตัว ถ้าเฉลี่ยแบบไม่ถ่วงน้ำหนัก tile ที่มีคนทดสอบน้อยจะมีน้ำหนักเท่ากับ tile ที่คนทดสอบเยอะ ส่วนจังหวัดของ NDT7 ระบุด้วยวิธีเดียวกันแต่อ้างอิงขอบเขต GADM 4.1 แล้วรวมข้อมูลจากรายการทดสอบโดยตรง

ทุก province-quarter ต้องผ่านเกณฑ์ความเพียงพอของข้อมูลก่อนคำนวณสถิติใดๆ ฝั่ง Ookla ใช้ `total_tests` ≥ 100 **และ** `n_tiles` ≥ 5 ส่วน NDT7 ใช้ `total_tests` ≥ 100 อย่างเดียว เกณฑ์นี้ไม่ตัดข้อมูลที่ไม่ได้หายไปอยู่แล้วออกเพิ่ม — ฝั่ง Ookla ไม่ตัดอะไรออกเลย จาก 9 ประเทศ ฝั่ง fixed มี 3,222 province-quarter เข้ามาและผ่านครบ 3,222 ฝั่ง mobile มี 3,184 เข้ามาและผ่านครบ 3,184 ผลกับฝั่ง NDT7 ไม่เท่ากันทุกประเทศ จำนวน test ฝั่ง cellular ลดลงทุกประเทศภายใต้เกณฑ์นี้ หนักสุดที่เวียดนาม ส่วนกัมพูชากับลาว ซึ่งเป็นสองประเทศที่มีข้อมูลน้อยที่สุดในงานนี้อยู่แล้ว เสียข้อมูลไปเยอะทั้ง fixed และ mobile เกณฑ์นี้จึงเป็นข้อจำกัดจริงสำหรับ NDT7 แต่เป็นแค่พิธีการสำหรับ Ookla

ก่อนรวมข้อมูล แถวดิบที่ไม่น่าเป็นไปได้ (throughput ≤ 0, duration ≤ 0 และลักษณะคล้ายกัน) ถูกกรองออกก่อนคำนวณสถิติใดๆ ทั้งสองแหล่งข้อมูล
