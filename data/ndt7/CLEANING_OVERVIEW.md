## 2. ขั้นตอน (pipeline)

```
ข้อมูลดิบจาก BigQuery
   │
   ├─ [1] Clean        ตัดแถวที่เป็นไปไม่ได้ทางกายภาพ (ข้อ 3)
   ├─ [2] Null check   ตรวจค่าว่าง
   ├─ [3] Label        ตรวจ IP จริงว่า mobile / hosting  ← v2 เปลี่ยนตรงนี้ (ข้อ 4)
   └─ [4] Province     ติดหน่วยพื้นที่ด้วย point-in-polygon (ข้อ 5)
        │
        ▼
   data/ndt7/<c>/mlab_<c>_clean.parquet
```

**ที่เปลี่ยนใน v2 คือขั้น [3] เท่านั้น** ขั้น clean / province / save ยังเป็นตัวเดิม

## 3. Clean ตัดอะไรทิ้ง

ตัดแถวที่ค่าเป็นไปไม่ได้ (ไม่ใช่การวัดจริง):
- `mean_throughput_mbps <= 0` (โหลดไม่สำเร็จ)
- `duration <= 0`
- `min_rtt < 0`
- `loss_rate` นอกช่วง [0, 1]

## 4. ⭐ ติด label ประเภทเน็ต — หัวใจของงาน (v2)

### กฎการแบ่ง 3 กลุ่ม

ip-api ส่ง `mobile` / `hosting` / `proxy` มาเป็น **boolean อิสระ 3 ตัว** การได้ 3 กลุ่มที่ไม่ทับกัน
เป็นผลของ**กฎลำดับที่เราตั้งเอง** (cellular ชนะ hosting เสมอ) ไม่ใช่ธรรมชาติของข้อมูล —
ต้องเขียนข้อนี้ใน limitation

## 8. Limitation ที่ต้องเขียนในเปเปอร์

1. **ไม่มี ground truth** — validate ได้แค่ความสม่ำเสมอภายในของ ip-api
   เคลมได้แค่ *"ทำซ้ำคำตอบ ip-api ณ วันหนึ่งได้ซื่อตรง"* **ห้าม**เคลมว่า *"แยก fixed/mobile ถูก"*
2. **นิยาม "mobile" อาจเปลี่ยน** — รอบล่าสุด ip-api ย้าย FWA/ดาวเทียม/ไฟเบอร์ไปเป็น fixed
3. **GADM 4.1 = ข้อมูลปี 2022** — อินโดได้ 34 จังหวัด ไม่ใช่ 38
4. **CGNAT** — unique IP ≠ unique user · สัดส่วน address ≠ สัดส่วน test
5. **การแบ่ง 3 กลุ่มเป็นผลของกฎลำดับ** ไม่ใช่ธรรมชาติของข้อมูล (ดูข้อ 4)
6. **TH ใช้ขอบเขตคนละแหล่ง** และ v1 ของ TH เคยใช้ 9 category ไม่มี hosting —
   TH เพิ่งเทียบกับประเทศอื่นได้เป็นครั้งแรกใน v2
7. **`0.019%` คือบล็อกที่ *ตรวจพบ* ว่าปน ไม่ใช่อัตราจริง** — k=5 จับ mixed block ได้ราว 58%
   เขียนในเปเปอร์ว่า **"detected"** เสมอ
